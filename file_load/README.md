# Youth Data Import Workflow

This directory contains scripts and data files for importing youth information into the youth-permission-tracker system.

## Overview

The import process works in two phases:

- **Phase 1 (Current)**: Create basic youth accounts with names and group assignments
- **Phase 2 (Future)**: Add medical/permission data to existing youth accounts

Current data includes: **40 youth** (19 males, 21 females) extracted from PDFs

## Quick Start

### 1. Extract Data from PDFs (Already Complete)

The data has already been extracted from the PDFs:
- YM Members.pdf: 19 males (10 Priests, 9 Teachers)
- YW Directory.pdf: 21 females (all YW)
- Result: `youth_data.json` with 40 entries

To re-extract (if PDFs change):
```bash
python extract_from_pdf.py
```

### 2. Review and Edit Data

Open `youth_data.json` and you'll see each youth with:

**Phase 1 Fields (Extracted from PDF):**
- `first_name`, `last_name`, `group`, `gender`, `age`
- `email` (where available in PDF)
- `birth_date` (extracted where available, ISO format)

**Phase 2 Fields (Placeholder "missing" values):**
All entries have these fields with "missing" values ready for you to populate:
- `permission_code`: 6-digit code
- `parent_guardian`: name, phone, email, relationship
- `medical`: conditions, medications, allergies, dietary_restrictions, limitations, special_accommodations
- `emergency_contact`: name, phone
- `signature`: signed_by, signature_image_base64
- `signed_at`: ISO timestamp

You can edit any "missing" values as you collect the data.

### 3. Load Data into the System

#### Dry Run (Validate Without Loading)
```bash
python load_youth_data.py --dry-run
```

This validates all 40 entries and shows what would be loaded.

#### Load for Real
```bash
python load_youth_data.py
```

This loads all youth from `youth_data.json` into the system via the `/youth` API endpoint.

**Required**: The API must be running (typically at `http://localhost:5000`)

## Configuration

Edit `loader_config.py` to customize:

| Setting | Purpose | Default |
|---------|---------|---------|
| `API_BASE_URL` | API endpoint base URL | `http://localhost:5000` |
| `DRY_RUN` | Enable dry-run mode by default | `False` |
| `SKIP_ON_DUPLICATE` | Skip duplicate usernames instead of failing | `True` |
| `SKIP_ON_VALIDATION_ERROR` | Skip invalid entries instead of failing | `False` |
| `SKIP_ON_API_ERROR` | Skip failed API calls instead of failing | `False` |
| `VERBOSE` | Print detailed progress messages | `True` |

### Override API URL

```bash
# Via environment variable
export YOUTH_API_URL="http://api.example.com:5000"
python load_youth_data.py

# Via command line
python load_youth_data.py --api-url http://api.example.com:5000
```

## API Details

The loader calls the **POST /youth** endpoint which:

- **Creates** a new youth account with a username formatted as `firstname_lastname` (lowercase)
- **Requires**: `first_name`, `last_name`, `group`
- **Returns**: `user_id` (the generated username)
- **Fails with 409 Conflict** if the username already exists

See `../api_base/main.py` (lines 347-393) for endpoint implementation.

## Error Handling

The loader handles these error scenarios:

| Scenario | Behavior |
|----------|----------|
| **Missing required field** | Skip entry (if `SKIP_ON_VALIDATION_ERROR=True`) or fail |
| **Duplicate username** | Skip entry (if `SKIP_ON_DUPLICATE=True`) or fail |
| **Invalid group** | Skip entry (if `SKIP_ON_VALIDATION_ERROR=True`) or fail |
| **API timeout** | Retry up to 3 times with 2-second delays |
| **API connection error** | Retry up to 3 times with 2-second delays |
| **API returns 500 error** | Retry, then skip or fail (based on config) |

Adjust error handling in `loader_config.py`.

## Common Issues

### "Cannot connect to API"
- Ensure the API is running: `python ../api_base/main.py`
- Check the URL: default is `http://localhost:5000`
- If using a different URL, set via `--api-url` flag or `YOUTH_API_URL` env var

### "Invalid JSON in youth_data.json"
- Run: `python -m json.tool youth_data.json`
- Fix any syntax errors (missing commas, quotes, brackets)
- Ensure all field values are properly quoted strings

### "PDFs don't extract correctly"
- The PDF structure may differ from what the script expects
- Manually extract the data and edit `youth_data.json` directly
- Or: contact the developer to adjust the PDF parsing logic

### "Duplicate username" errors on re-run
- This is normal - the script skips duplicates by default
- To load different data, manually edit `youth_data.json` first
- Or: reset the database and re-run
